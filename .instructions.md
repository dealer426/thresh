## Live Mobile Session — Phone Notification Protocol

The user monitors and controls Copilot from their phone via the ntfy app. Treat the ntfy questions topic as a **live activity feed** — the user is watching. Stream your actions so they can follow along and jump in anytime.

### Scripts Location
- **Two-way (blocking question):** `c:\Users\burns\source\repos\thresh\notify-and-wait.ps1`
- **One-way (FYI update):** `c:\Users\burns\source\repos\thresh\notify-phone.ps1`

### LIVE FEED — Narrate your work:
Send a one-way notification for EVERY significant action so the user sees a real-time log on their phone:

- Starting a new step
- Running a command and its result (pass/fail)
- Editing a file (which file, what change)
- Completing a step

```powershell
pwsh -File "c:\Users\burns\source\repos\thresh\notify-phone.ps1" -Message "Starting: running dotnet build on thresh-hub..." -Title "Step 2/5" -Priority 2
```
```powershell
pwsh -File "c:\Users\burns\source\repos\thresh\notify-phone.ps1" -Message "dotnet build succeeded (0 warnings). Editing Program.cs to add SQLite config." -Title "Step 2/5" -Priority 2
```
```powershell
pwsh -File "c:\Users\burns\source\repos\thresh\notify-phone.ps1" -Message "Step 2/5 DONE: Build passing, config updated." -Title "Step 2 Complete"
```

Keep messages short — the user is reading on a phone screen. One action per message.

### CHECK FOR USER INPUT — Between every step:
After each major action, check if the user sent a message by polling the response topic. If they did, follow their direction:

```powershell
$check = pwsh -File "c:\Users\burns\source\repos\thresh\notify-and-wait.ps1" -Message "Step 2 done. Moving to step 3 (deploy). Reply to redirect or I'll continue in 30s." -TimeoutMinutes 1
```

If the user replies with new instructions mid-task, pivot to follow them. If timeout, continue with the plan.

### Approval flow for risky actions:
For destructive or hard-to-reverse actions (git push, delete files, deploy, DB changes), ALWAYS use notify-and-wait even if you think you know the answer:

```powershell
pwsh -File "c:\Users\burns\source\repos\thresh\notify-and-wait.ps1" -Message "Ready to git push force to origin/main (3 commits, rebased). Approve/Reject?"
```

### Session heartbeat:
If working on a long task (>10 minutes between milestones), send periodic FYI updates so the user knows you're still running:

```powershell
pwsh -File "c:\Users\burns\source\repos\thresh\notify-phone.ps1" -Message "Still working: building thresh-hub Docker image (running for 8 min, no errors yet)." -Priority 2
```

### Error recovery:
If you encounter an error, try to fix it yourself first (up to 3 attempts). If you still can't resolve it, notify with full error context:

```powershell
pwsh -File "c:\Users\burns\source\repos\thresh\notify-and-wait.ps1" -Message "STUCK after 3 attempts. Task: building thresh. Error: 'dotnet restore failed - NuGet source unreachable'. Tried: clearing cache, alternate source. Need guidance or should I skip this step?" -Title "Copilot Stuck"
```

### Interactive / physical input required:
If a terminal is prompting for a password, passphrase, MFA code, sudo, or any interactive input that you cannot provide — OR if a GUI window needs focus/interaction:

1. Do NOT try to type passwords or bypass prompts.
2. Send a HIGH PRIORITY notification explaining exactly what's needed:

```powershell
pwsh -File "c:\Users\burns\source\repos\thresh\notify-and-wait.ps1" -Message "NEED PHYSICAL INPUT: Terminal is prompting for git SSH passphrase. Please remote in or come to desktop. I'll wait." -Title "Desktop Access Needed"
```

3. Wait for the user to respond "done" (meaning they've entered it remotely/physically) before continuing.
4. Include which terminal and what prompt is showing so the user can find it quickly via remote desktop.
